# prompts/ 使用说明

八个提示词不是并列的，而是一条流水线。**顺序错了效果会差很多**：先定创新点，再立骨、搭架、逐段写，最后精修与成图。

```
p7 创新点 ──► innovation.md（AI 提名，作者决定）
                │
p1 立骨 ──► paper_ir.json（thesis / claims / evidence）
                │
                ▼
p2 搭架 ──► sections + 段落任务单（每段一个任务）
                │
                ├──► p3 + p8 行文（一次一段，断言句带证据编号）──► p4 精修（只删改，不加料）
                │                                  │
                └──► p5 成图（claim → FigureSpec）─┴──► p6 审稿（四角色 → finding）
                                                              │
                                                              └──► 回到 p3/p5 修，或回 p1 改主张
```

## 怎么喂

| 步骤 | 输入 | 关键点 |
|---|---|---|
| p1 | 一句话想法 + 已有材料 | 不要一次给太多；材料多时先给"结论性结果"，细节留给 p3 |
| p2 | `paper_ir.json` | 只给 IR，不要给全文；让模型专注结构 |
| p3 | **一张**任务单 + 该段证据 + 上一段末句 | 一次只写一段。一次给三张任务单，模型必然写成三段并列 |
| p4 | 一段草稿 + strength | 强调"只删改，不加料"；给它证据 JSON 作为只读约束 |
| p5 | 一条 claim + 数据 schema | 不要给整篇；图想说的越少，图越好 |
| p6 | 全文 + IR + 图 | 四角色要分开跑或明确要求"独立判断"，否则会互相锚定 |
| p7 | `facts.md` + 近邻工作 | AI 只提名候选，作者决定接受/改写/拒绝；没有证据的候选只能标弱 |
| p8 | 一张段落任务单 + 本节证据包 + 文献包 | 每个断言句带 `[E-xxxx]`；证据不够就输出 `INSUFFICIENT_EVIDENCE`，不要圆场 |

## 三个实操建议

1. **每次调用只做一件事。** 让模型"顺便把下一段也写了"是质量崩塌的开始。
2. **把 IR 当作唯一真相。** 模型在正文里想加新主张时，让它输出 `IR_PATCH_SUGGESTION`，由你决定是否合并。
3. **保留失败记录。** `INSUFFICIENT_EVIDENCE`、`CONFLICT`、`IR_PATCH_SUGGESTION` 这些输出比"写得不错"有价值得多——它们告诉你卡在哪。
