# 11 · 论文工具的复用架构

> 目标：换一篇遥感论文，仍能产出这次的水平。不是复用某一篇的句子，而是复用**语料画像、结构模板、检查器与流水线**。
> 一句话：**工具管「像不像、通不通、站不站得住」，人管「新不新、对不对、值不值得写」。**

---

## 1 可复用的四层

| 层 | 内容 | 复用方式 | 换论文时是否重做 |
|---|---|---|---|
| **语料层** | 摘要/方法/结果/讨论的分节画像；术语白名单与黑名单 | 每个目标期刊建一次，所有论文共用 | 换期刊才重做 |
| **结构层** | 四方向骨架、章节任务、段落任务单模板 | 直接复用；按论文类型选模板 | 否 |
| **检查层** | 语体检查、术语检查、数字溯源、红线检查 | 直接运行 | 否 |
| **生成层** | 分节提示词（p1–p6 + 章节提示词） | 随模型换代替换 | 否，但需版本管理 |

不可复用的是**内容**：项目事实、命题、方法组件、实验数字。这些每篇都要重做，且必须由人确认。

---

## 2 一篇论文的七个阶段

```
① 项目事实清单（人+脚本，只列数与条件）
② 命题与证据（人定 thesis/claims，AI 起草）
③ 章节骨架（四方向模板 + 段落任务单）
④ 分节生成（按画像，一次一节）
⑤ 图表规划（claim → FigureSpec）
⑥ 检查（语体/术语/数字/红线/主张覆盖）
⑦ 定向重写（只改 fail 项）→ 摘要最后写
```

每阶段的产物是文件，不是对话记忆：

```
project/
├── project.json          # 期刊、语言、模板、画像 id
├── facts.md              # 事实清单（数字唯一来源）
├── paper_ir.json         # thesis / claims / evidence / directions
├── outline.md            # 章节骨架 + 段落任务单
├── manuscript.md         # 正文
├── checks/report.md      # 检查报告
├── figures/spec/         # 图表规格
└── refs/                 # 参考文献
```

---

## 3 换一篇遥感论文，具体怎么走

### 3.1 立项（10 分钟）

```bash
py tools/new_project.py --name "另一篇遥感论文" --dir projects/xxx
```

生成上表目录与模板。在 `project.json` 里填目标期刊、语言、画像 id（默认 `rs_abstract` / `rs_method` / `rs_results` / `rs_discussion`）。

### 3.2 事实清单（人做，最花时间）

把项目里的数据、实验记录、日志、结果表倒进 `facts.md`。规则只有一条：**每个数字只能出现一次，且必须带来源**。正文里的数字只能引用事实清单，不能新造。

### 3.3 命题与证据（人定，AI 起草）

`paper_ir.json` 至少包含：

- `thesis`：一句话，含对象、干预、效应、条件；
- `claims`：3–4 条，对应四个方向；
- `evidence`：每条 claim 绑定事实清单里的数字或文献；
- `directions`：数据检查、预处理、骨干、后处理，各自的约束与证据。

### 3.4 骨架（模板 + 人改）

`outline.md` 用四方向模板：每章一个修辞任务，每节 2–4 个段落任务单（claim_ref、move、exit_belief、字数）。章末必须有交接句。

### 3.5 分节生成（一次一节）

按 `outline.md` 的任务单，用 `prompts/` 里的提示词逐节生成；方法章不报增量，数字留到实验章。每节生成后立刻跑检查，不攒到最后。

### 3.6 检查（自动）

```bash
py tools/check_project.py --dir projects/xxx
```

输出 `checks/report.md`，包含语体分数、术语命中、数字溯源、红线扫描、主张覆盖。任何一项 fail，只改那一项。

### 3.7 汇总（摘要最后写）

正文定稿后再写摘要，用 `rs_abstract` 画像；摘要通过后再生成对照版与版本记录。

## 4 质量契约（工具必须能判）

| 项 | 判据 | 谁判 |
|---|---|---|
| 方法主线 | 有命名框架、四方向、章末交接 | 人 + 规则 |
| 语体 | 分节 `style_check` ≥ B，摘要 ≥ A | 工具 |
| 术语 | 自造词 < 2 次/千汉字；一概念一名 | 工具 |
| 数字 | 正文数字都能在 `facts.md` 找到 | 工具 + 人 |
| 红线 | 不比较、归属、两段不混加、查表换干净划分为 0、配额有前作 | 规则 + 人 |
| 主张覆盖 | 每条 claim 至少一段兑现 | 规则 |
| 图表 | 一图一 claim，图注首句即断言 | 人 + 规则 |

---

## 5 领域适配：换期刊、换子领域

| 变化 | 要做什么 | 工作量 |
|---|---|---|
| 换期刊（仍遥感） | 抓 100+ 摘要、50+ 全文，重建分节画像；更新术语白名单 | 半天 |
| 换子领域（遥感→医学影像） | 重建画像；重写四方向模板（数据/表示/模型/后处理仍适用，但约束不同） | 2–3 天 |
| 换语言（中→英） | 单独建英文画像；术语表双语；句式规则换一套 | 1 周 |
| 换论文类型（方法→综述） | 换骨架模板；检查项改为覆盖度、分类框架、文献支持 | 2–3 天 |

画像与术语表是**资产**，越用越准；提示词是**耗材**，随模型换代。

---

## 6 自动化边界

| 能自动 | 只能半自动 | 必须人做 |
|---|---|---|
| 语料抓取与画像 | 事实抽取（从日志/结果表） | thesis 与 claims |
| 语体/术语检查 | 骨架生成 | 方法组件的取舍 |
| 数字溯源 | 分节草稿 | 实验解释与边界 |
| 红线扫描 | 图表规格 | 归属与伦理判断 |
| 版本对照 | 摘要压缩 | 最终定稿 |

工具的价值不是替人写，而是**把人从“像不像、通不通”里解放出来，只做“新不新、对不对”**。

---

## 7 路线图

| 版本 | 形态 | 能力 |
|---|---|---|
| **v0（现在）** | 目录模板 + 两个检查器 + 提示词 | 人能跑通一篇；检查靠命令行 |
| **v1** | `new_project` + `check_project` + 事实抽取脚本 | 半自动；换期刊只需重建画像 |
| **v2** | Web 工作台：论证台、骨架台、正文台、图表台 | 实时检查、定向重写、版本对照 |
| **v3** | 多论文并行、期刊画像库、审稿模拟 | 团队使用 |

---

## 8 一句话

**复用不是复用这篇文章，而是复用“画像—模板—检查器—流水线”这套基础设施；每篇新论文只重做事实、命题与证据。**
