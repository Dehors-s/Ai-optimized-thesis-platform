# 18 图表语法与生成

> 回答需求 3 的第一层：单张数据图从"需要印证和展示的内容"出发，设计排版优美凝练。
> 复杂图（地学复合图、矩阵、架构图）与工具链见 [docs/19](19-复杂图表的技术路线.md)。
> 本文先看真实论文怎么做（10 篇 arXiv，12 张图入册、14 张实际看过；
> 样本表与逐图点评见 [corpus/figures/field/notes.md](../corpus/figures/field/notes.md)），
> 再给出一套可执行的选型与版式规则，最后是 `tools/figspec.py` 的 v0 实现。

---

## 0 结论

图表不是"把数据画出来"，而是**选一种比较，让读者不得不承认一句话**。

所以顺序必须是：

```
主张 → 该主张需要哪种比较 → 数据能不能支撑这个比较 → 图型 → 版式 → 图注 → 检查
```

而不是"我有这些数据，画个柱状图吧"。数据是约束，不是起点。

我们的做法落成三件事：

1. **图必须绑定 claim**，没有 claim 的图不生成；
2. **图型由比较结构决定**，不由数据类型决定；
3. **图注是断言**，不是标签；检查器查图注有没有说清"这张图证明了什么"。

### 1.1 一个反例

[DCT-Mamba3D 图 5](../corpus/figures/field/2502.01986-fig5.png) 的 t-SNE 六宫格：
六个面板共用固定坐标 `[-100,100]`，数据只占中心约 15%，其余是死白；
没有 (a)–(f) 标号，没有面板内方法名；同一套 13 类色条重复画了 6 遍。

三个问题都属同一类：**图没有为"比较"服务**。坐标不贴合数据，面板不自足，墨迹重复。
这正好是第 3 节几条规则的来源。

### 1.2 三条骨架，互不通用

| 骨架 | 回答的问题 | 版式 | 典型错误 |
|---|---|---|---|
| 论证型（对比 / 标尺） | 为什么这么做 | 同构多行，只变一个变量 | 每行结构都不一样，读者无法对照 |
| 结构型（架构 / 流程） | 怎么工作 | 水平主链 + 垂直挂载 + 虚线放大 | 节点太多、字号太小、图例太大 |
| 证据型（网格 / 曲线 / 矩阵） | 结果如何 | 行=样本、列=条件、末列=GT；或曲线+区间 | 面板不自足、轴不贴数据、用分组柱状图 |

一个反例也值得记：不少论文的图注写得很长，但正文只有一句 "As shown in Fig. X"。
图被当成插图，不是论据。我们要反过来：**正文说清这张图支持哪一句，图注说清这张图怎么读。**

## 2 从内容到图型

先问"要证明什么"，再查表：

| 要证明的事 | 数据结构 | 首选 | 不要用 |
|---|---|---|---|
| A 比 B 高/低（差异小） | 2—6 个类别 × 1 个数值 + 区间 | **点图 + 误差条 + 参照带** | 从 0 起的柱状图（会把 5% 的差异压成一条缝） |
| 分步贡献 | 有序步骤 × 增量 | **瀑布图**，不显著的一步用斜纹/灰 | 堆叠柱状图（看不出顺序） |
| 随参数变化 | 连续 x × y（±区间） | **折线 + 置信带** | 双 Y 轴、3D 折线 |
| 多类混淆 | 类别 × 类别 | **行归一化热力图**，直接标数值 | 只给总体准确率 |
| 方法在哪些样本上有效 | 样本 × 条件 | **定性矩阵**（行样本、列方法、末列 GT） | 挑最好看的几张拼在一起 |
| 系统怎么工作 | 组件 + 数据流 | **管线图**（同一视觉语法，差异染色） | 复杂到需要图注解释每个框 |
| 两个指标的权衡 | 两列数值 | **散点 + Pareto 前沿** | 双轴柱状图 |
| 一个数 vs 一个阈值 | 单值 + 区间 | **点图 + 阈值线** | 饼图、仪表盘 |

判断口诀：**能比位置就不比长度，能比长度就不比面积，能比面积就不比颜色。**

## 3 版式规则（可直接 lint）

| 项 | 规则 | 原因 |
|---|---|---|
| 物理尺寸 | 单栏 3.5 in，双栏 7.2 in；高度不超过宽度的 1.4 倍 | 排版时不再缩放，字号才可控 |
| 字号 | 正文 8—9 pt，刻度 7—8 pt，最小 7 pt | 缩到栏宽后仍可读 |
| 颜色 | Okabe-Ito 色盲安全表；一个强调色 + 灰 + 黑 | 黑白打印、色盲读者 |
| 标注 | 关键数值直接标在图上；不标所有值 | 减少图例与心算 |
| 误差 | 有区间就画；没有就说明"单次运行" | 不画区间等于暗示确定性 |
| 参照 | 噪声下限、随机基线、SOTA 用带/线标出 | 让"差多少算差"可见 |
| 基线 | 柱状图默认 0 基线；差异 <20% 时改用点图或差值图 | 0 基线会压缩小差异 |
| 标题 | 图内不放标题，交给图注首句 | 避免标题与图注重复 |
| 面板 | (a)(b)(c) 放子图下方，字号与刻度一致 | 阅读顺序 |
| 网格 | 默认无；需要时只留浅色水平线 | 减少 ink |
| 边框 | 去掉上、右边框 | 减少 ink |
| 留白 | 大于边框；标签不压数据 | "凝练"来自留白 |
| 单位 | 轴标题带单位；有效数字全图统一 | 审稿人会数小数位 |
| 面板自足 | 每格写方法名 + 关键指标，或图注逐格列全 | 读者不该做 6—8 次图注映射 |
| 编号 | 数字=阅读顺序（≤6），字母=并列面板 | 两套编号混用会乱 |
| 图例 | ≤3 条；能直接标在块上/箭头上的就不进图例 | 图例是最贵的墨 |
| 墨迹 | 轴范围贴合数据；色条只画一次；删重复图例 | t-SNE 反例：85% 死白 |
| 旋转 | 竖排旋转标签视为失败信号 | 缩印后基本不可读 |
| 首图 | 只讲立场；方法细节留给 Fig. 2 | 第一张图决定读者要不要继续读 |
| 消融 | 优先曲线（可断轴）或开关矩阵，不用分组柱状图 | 顶会消融的通行骨架 |

## 4 图注模板

三段式，不超过 120 字（中文）：

```
图 N  <断言：这张图证明了什么>。
<怎么读：横轴/纵轴/颜色/阴影分别是什么，区间是什么>。
<边界：差多少，是否低于噪声，因此主张到什么程度>。
```

好例子（来自 2503.16653 图 1 的写法，改写为中文）：

> 图 1 本文模型在吞吐上是对照的 1.8 倍（81.9 vs 45.0 t/s），精度不降。
> 横轴为批量大小，纵轴为每秒 token 数；阴影为三次运行的极差。
> 在批量 1—8 区间优势稳定，批量 32 时差距收窄到 1.2 倍。

坏例子（常见）：

> 图 1 不同方法的性能对比。

问题：没有断言、没有怎么读、没有边界。

检查器至少能查：图注是否包含 claim 编号、是否包含数字或方向词、是否超过长度。

## 5 生成流程

```
1. claim        这张图支持哪条主张（C-xx），一句话
2. comparison   要证明"A 比 B 好/差/相当"，还是"随 x 变化"，还是"错在哪"
3. data gate    数据够不够画这个比较；不够就 INSUFFICIENT_EVIDENCE，不画
4. type         查第 2 节的表，选图型
5. spec         写 FigureSpec（轴、编码、标注、参照、图注）
6. render       确定性渲染（matplotlib / TikZ / Graphviz），不用图像生成
7. lint         机器检查第 3 节规则
8. read-back    遮住图注，问一个没看过正文的人：这张图说明了什么？
                答不出 → 回第 2 步，不是回第 6 步调颜色
```

第 3 步和第 8 步是大多数工具没有的：

- **数据门**：没有对照、没有区间、没有噪声参照，画出来只会暴露问题；
- **读回**：图是给人看的，不是给指标看的。遮住图注还能读出结论，才算成立。

## 6 `figspec` v0

`tools/figspec.py` 实现了 7 种图型：`dot` / `waterfall` / `line` / `bar` / `heatmap` / `pipeline` / `map`（Natural Earth 底图，无 Cartopy 依赖）。

```bash
py tools/figspec.py demo   --out figures/demo
py tools/figspec.py render --spec figures/demo/F1.json --out figures/demo
py tools/figspec.py lint   --spec figures/demo/F1.json
```

规格是一个 JSON，核心字段：

```json
{
  "id": "F1",
  "claim": "C-03",
  "type": "dot",
  "xlabel": "宏平均 F1 变化（×10^-3）",
  "unit": "×10^-3",
  "categories": ["数据预处理", "异构骨干", "训练后处理", "对照"],
  "values": [6.0, 4.6, 1.4, 0.0],
  "ci": [[5.2, 6.8], [3.9, 5.3], [0.9, 1.9], [0.0, 0.0]],
  "reference": {"band": [1.8, 2.2], "label": "噪声下限"},
  "highlight": "训练后处理",
  "caption": "图 1 训练后处理的增益为 0.0014，低于 0.002 的噪声下限（C-03）。..."
}
```

三张示例（`figures/demo/`）：

| 图 | 类型 | 证明了什么 | 设计点 |
|---|---|---|---|
| F1 | 点图 | 后处理增益低于噪声下限 | 误差条 + 灰带 + 单点强调，不用柱状图 |
| F2 | 瀑布图 | 三项改动的累计贡献 | 不显著的一步用斜纹灰，避免误读 |
| F3 | 管线图 | 四段流程的分工 | 同色系，只把重点段染成橙色 |
| F4 | 地图 | 全球站点分布 | Natural Earth 底图 + 对数色标，可作地学面板 |

lint 已能查：claim 是否进图注、图注是否为空、轴标题/单位、尺寸、配色、数据是否为空，
以及一条"内容型"规则：**柱状图从 0 起且组间差异 <20% 时报警**——这正是我们在
测试里踩到的坑：0.71 vs 0.69 的差异，在一张 0 基线的柱状图里几乎看不见。

## 7 我们踩过的坑（真实）

1. **标签出界，整张图被 bbox 拉成一条**：瀑布图的数值标签用了绝对偏移 0.02，
   而数据范围只有 0.008，标签跑到坐标轴外，`bbox_inches="tight"` 把画布撑大，
   图被压成底部一条。改为相对偏移（范围的 5%）+ 显式 ylim。
2. **字体缺字**：`×10⁻³` 的上标减号在微软雅黑里没有，渲染时告警并显示方框。
   改用 `×10^-3` 或 `10^-3`。
3. **图例压数据**：分组柱状图的图例用 `loc="best"`，直接盖在柱子上。
   改成图例放轴外上方。
4. **0 基线压缩差异**：0.71/0.69 的对比在 0 基线柱状图里看不出差别。
   这类比较应该用点图或差值图；lint 已加规则。
5. **热力图轴标签拥挤**：`真实类` 与刻度标签挤在一起，需要 `labelpad` 和留白。
6. **图注写成标签**："图 1 不同方法的性能对比"——没有断言，读者无法判断该看哪。

这些坑的共同点：**不是审美问题，是信息问题**。图没把该比的比出来，再漂亮也没用。

## 8 还没做的

- 多面板组合：`(a)(b)(c)` 的自动对齐、共享轴、统一色标；
- 定性矩阵：图像网格 + 列标题 + 末列 GT；
- 导出 LaTeX/TikZ 与期刊模板（单双栏、字号、图注格式）；
- 读回评审：接一个视觉模型，遮住图注问"这张图说明了什么"，与 claim 比对；
- 表与图的分工：什么时候该用表（精确值、多指标），什么时候该用图（趋势、比较）；
- 中文期刊图注格式（"图 1" vs "Fig. 1"、中英对照）。

## 9 一句话

**图的起点是 claim，终点是读者能复述的那句话；中间的所有设计，都是为了减少复述的成本。**
