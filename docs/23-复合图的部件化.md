# 23 复合图的部件化：从"画一张图"到"拼装语义部件"

> 你说得对：复合图是多个部分拼起来的，应该逐个处理，而不是整张画布硬画。
> 画图和写文章确实同构：先决定"这段要表达什么"，再选表达方式，最后用版式和素材装饰。
>
> 这一版先联网核对主流方法，再给出我们的部件化架构。

---

## 0 结论

复合图 = **语义部件（panel）× 拼装（composition）× 风格（style）**。

- **部件**：地图、分布、矩阵、架构堆叠、分类头、流形/向量场/谱……每种是一个独立渲染器，有输入规格、能单独测试。
- **拼装**：容器、网格、共享色标/轴、字母、箭头、留白。这部分是版式，不是画工。
- **风格**：字体阶梯、配色角色、线宽、图标/图片素材。统一风格让拼装结果"像一张图"。

写文章的同构关系：

| 写文章 | 画图 |
|---|---|
| 段落 | 面板（panel） |
| 小节 | 容器（container） |
| 过渡句 | 连接箭头/字母 |
| 主题句 | 图注首句 |
| 文风/排版规范 | 字体、配色、线宽 |
| 提纲 | 版式模板 |

## 1 联网核对：主流方法都在"拆部件"

| 工作 | 做法 | 对我们的意义 |
|---|---|---|
| [FigTree, arXiv:2609.01006](https://arxiv.org/abs/2609.01006) | 图 → 层级局部区域 → 每区一段 SVG → 拼装；render-critic 修 | 部件化 + 可编辑 + 评审回路 |
| [Crafter, arXiv:2605.30611](https://arxiv.org/abs/2605.30611) | 图是离散语义组件的组合；harness 管生成与编辑 | 组件库 + 编辑 |
| [LiveFigure, arXiv:2605.23527](https://arxiv.org/abs/2605.23527) | 参考图 → blueprint → PPTX 技能 → 视觉诊断 | 先学参考图，再按技能拼 |
| [VisPainter, arXiv:2510.27452](https://arxiv.org/abs/2510.27452) | Manager/Designer/Toolbox 三角色，元素级矢量 | 角色分工 + 元素可编辑 |
| [DiagrammerGPT, arXiv:2310.12128](https://arxiv.org/abs/2310.12128) | planner-auditor 生成 diagram plan，再渲染 | 先布局计划，再画 |
| [See it. Say it. Sorted., arXiv:2508.15222](https://arxiv.org/abs/2508.15222) | VLM critic + LLM 生成 SVG，Judge 选优 | 评审驱动迭代 |
| [ChartCoder, arXiv:2501.06598](https://arxiv.org/abs/2501.06598) | 图表 → 代码，保证无损可编辑 | 数据图走代码 |

共同点：**没有一家在"整张图一次生成"上取胜**，都是拆部件、生成矢量、评审修正。

## 2 四层架构

```
L1 内容计划    claim → 视觉句子（比较/趋势/结构/分布/定性/空间）
L2 部件库      panel renderer + panel spec（可单独渲染、单独测试）
L3 拼装器      layout + containers + shared + connectors + letters
L4 评审         overlay/diff + 结构清单 + 人工/VLM 抽检
```

### L1 内容计划

先决定每一块"要证明什么"，再选视觉句子：

| 要表达 | 视觉句子 | 部件 |
|---|---|---|
| 空间格局 | 地图 | map |
| 趋势 | 折线/时序网格 | line / grid |
| 分布差异 | 小提琴/箱线/直方图 | distribution |
| 多条件对比 | 矩阵小倍数 | matrix |
| 结构 | 框+箭头 | flow / cnn-stack |
| 定性结果 | 图像网格 | qualitative-grid |
| 机制 | 数学示意 | manifold / vector-field / spectra |

### L2 部件库

每个部件是一个函数：

```python
render(ax, spec) -> None
lint(spec) -> list[str]
```

约定：

- 只画在自己的 axes 里，坐标 0—1，不关心全局位置；
- 输入是 spec（数据/标签/颜色），输出是矢量元素；
- 能单独导出 PNG/PDF 做视觉验收；
- 不依赖其他部件。

### L3 拼装器

```json
{
  "canvas": [10.0, 8.95],
  "containers": [
    {"rect": [0.006, 0.711, 0.37, 0.278], "letter": "a", "panel": "manifold",
     "title": "Manifold with Boundary Representation for Images", "color": "green"}
  ],
  "connectors": [{"from": "a", "to": "b"}]
}
```

拼装器只做四件事：放容器、调部件、画共享元素、连箭头。**它不画数据。**

### L3.1 拼装层 lint

`panelkit compose` 会自动跑几何检查，也可以单独跑：

```bash
py tools/panelkit.py lint --layout figures/repro/MTDL_layout.json
py tools/panelkit.py compose --layout figures/repro/MTDL_layout.json --strict
```

| 规则 | 查什么 | 严重度 |
|---|---|---|
| C0 | 容器少于 2 个 | warn |
| C1 | 容器越界（x/y/w/h 超出 0—1） | fail |
| C2 | 容器两两重叠 | fail |
| C3 | 间距 <0.003 | warn |
| C4 | 字母缺失/重复 | fail/warn |
| C5 | 面板未在 panelkit 注册 | fail |
| C6 | 标题按字数估算会溢出容器 | warn |
| C7 | 面板内框 <0.04×0.04 | warn |
| C8 | 标题重复 | warn |
| C9 | 共享色标：range/placement、面板存在、重复 id、重复色标 | fail/warn |
| C10 | 行标签：面板存在、归属唯一、底缘/高度/宽度/间距一致 | fail/warn |
| C11 | 列标签：面板存在、归属唯一、左缘/高度/宽度/间距一致 | fail/warn |
| C12 | 顶边对齐应等高、左边对齐应等宽 | warn |
| C13 | 共享色标范围是否覆盖面板 `data_range`；面板是否自带色标；刻度是否越界 | fail/warn |

共享元素在 layout 里声明：

```json
"shared": {
  "colorbars": [
    {"id": "cb_precip", "label": "Precipitation (mm)", "cmap": "YlGnBu",
     "range": [0, 300], "placement": "right", "ticks": [0, 100, 200, 300],
     "panels": ["a", "b", "c", "d", "e", "f"]}
  ],
  "row_labels": [
    {"text": "MPAS-O", "panels": ["a", "b", "c"]},
    {"text": "ROMS", "panels": ["d", "e", "f"]}
  ],
  "column_labels": [
    {"text": "Δx = 10 km", "panels": ["a", "d"]}
  ]
}
```

`compose` 会按声明只画一次共享色标、行标签、列标签；lint 检查重复、越界、对齐。

部件元数据（容器可覆盖）：

```json
{
  "panel": "map",
  "spec": {"data_range": [0, 300]},
  "panel_meta": {"has_colorbar": false}
}
```

- `spec.data_range`：面板数据的实际范围，用于和共享色标比对；
- `panel_meta.has_colorbar`：面板是否自带色标，自带则与共享色标预警；
- `panel_meta.data_range`：不想改 spec 时覆盖范围。

C13 的判定：共享色标 `range` 必须覆盖所有 `panels` 的 `data_range`（否则 fail）；
面板自带色标 → warn；刻度不在 range → warn；无 `data_range` → warn（无法核验）。

`--strict` 时有 fail 直接终止，不产出图。
MTDL 布局当前 PASS；坏 layout 能报出越界、重叠、重复字母、未注册面板、面板过小、标题溢出。
共享布局示例：`figures/repro/matrix_layout.json` → `figures/repro/matrix_shared.png`。

### L4 评审

- overlay：原图/复刻 50% 叠加，看边界；
- diff：差异图定位；
- 结构清单：面板数、容器坐标、文字、色标、箭头；
- 人工/VLM 抽检：遮住图注问"这张图说明了什么"。

## 3 MTDL 应该怎么拆

| 容器 | 部件 | 可复用性 |
|---|---|---|
| a 流形表示 | `manifold-panel`（离散网格 + 形状 + 两条边界条件） | 图论/拓扑论文 |
| b 向量场 | `vector-field-panel`（网格 + 区域 + 箭头） | 物理/数学 |
| c Hodge 谱 | `spectra-panel`（谱线 + 波形盒 + 公式） | 信号/谱方法 |
| d Hodge 分解 | `decomp-panel`（4 场 + 运算符 + 4 blob） | 分解类方法 |
| e CNN | `cnn-stack-panel`（堆叠 + 残差 + N×） | 所有网络图 |
| f 分类 | `classification-panel`（类别形状 + softmax） | 分类论文 |

拼装：六个容器按百分比放置，connectors 只画 a→b/c、b/c→d、d→e、e→f。

这样每块可以单独改、单独测；MTDL 不再是一张 400 行的画布脚本。

## 4 现在做了什么

`tools/panelkit.py`：一个最小部件库 + 拼装器 + 部件验收页。

```bash
py tools/panelkit.py list
py tools/panelkit.py demo --out figures/repro/panels
py tools/panelkit.py compose --layout figures/repro/MTDL_layout.json --out figures/repro/MTDL_panelkit
```

已实现 7 个部件：

- `cnn-stack`：竖向堆叠 + 残差 + N×；
- `classification`：normal/malignant/benign + softmax；
- `spectra`：谱线 + 波形盒 + 公式；
- `vector-field`：网格 + 区域 + 箭头；
- `manifold`：三个子面板（离散流形 → 图像 → 离散流形）+ 边界条件；
- `decomp`：4 场 + 运算符 + 4 blob；
- `map`：Natural Earth 底图 + 经纬网 + 散点（无 Cartopy 依赖）。

部件页：`figures/repro/panels_contact.png`。

**MTDL 已迁移**：`figures/repro/MTDL_layout.json` + `panelkit compose` 生成
`figures/repro/MTDL_panelkit.png`。六个容器各自调用一个部件，拼装器只负责坐标、
边框、字母和标题；手绘版 `repro_mtdl.py` 暂时保留作细节参照，下一步退休。

## 5 和之前的关系

- `figspec` 是**数据面板**库（点图/线/柱/热力/地图/管线）；
- `archspec` 是**架构部件**库（链/分支/放大/竖排）；
- `panelkit` 是**拼装器 + 语义部件**（把前两者和专用部件组合）；
- `repro_*` 是**验收用例**，不再是产品代码。
