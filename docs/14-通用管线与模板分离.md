# 14 · 通用管线与项目专属模板分离

> 目标：产品骨架不依赖任何一个项目；四方向、某期刊画像、某项目的红线，全部下沉为「配置」。
> 一句话：**管线是通用的，模板是分层的，项目是可替换的。**

---

## 1 目录分层

```
tools/                        通用管线（代码）
├── paperkit.py               CLI：new / check / terms / profiles
├── new_project.py            按类型与期刊生成项目
├── check_project.py          按配置检查
├── style_check.py            语体打分
├── term_check.py             术语体检
├── profile_registry.py       画像解析
└── build_*.py                画像构建

paperkit/
├── profiles/registry.json    「期刊 × 语言 × 学科 → 画像」注册表
├── templates/
│   ├── generic/              通用模板（facts.md、paper_ir.json）
│   └── types/                按论文类型（empirical/engineering/survey/systems/theory）
└── examples/engineering-rs/  四方向示例（项目专属，不作默认）

corpus/profiles/              语料统计产物（rs_* / cs_* / generic_zh_*）
projects/<name>/              每个项目自己的事实、命题、分解、规则、正文
```

**边界**：`tools/` 与 `templates/generic` 是产品；`templates/types` 是可扩展的通用类型；`templates/examples` 与 `projects/` 是项目专属。

---

## 2 画像注册表

`paperkit/profiles/registry.json`：

```json
{
  "defaults": {"zh": {"abstract": "generic_zh_abstract", "...": "..."}, "en": null},
  "entries": [
    {
      "journal": "测绘学报",
      "language": "zh",
      "discipline": "remote_sensing",
      "profiles": {
        "abstract": "rs_abstract",
        "method": "rs_method",
        "results": "rs_results",
        "discussion": "rs_discussion"
      }
    }
  ]
}
```

解析顺序：

1. `journal + language + discipline` 精确匹配；
2. `journal + language`（忽略学科）；
3. `language` 默认（`generic_zh_*`）；
4. 都没有 → `profiles = null`，检查器跳过语体项并提示，不阻断结构检查。

这样新期刊第一次使用时至少能跑通用画像，不会因为「没有 rs_*」而无法工作。

## 3 论文类型模板

| 类型 | 角色序列 | 适用 |
|---|---|---|
| `empirical` | 引言 → 相关工作 → 问题/数据 → 方法 → 实验 → 讨论 → 结论 | 有对照实验的方法论文 |
| `engineering` | 引言 → 问题 → 方法（多章，按分解）→ 实验 → 讨论 → 结论 | 工程实践、竞赛复盘 |
| `systems` | 引言 → 相关工作 → 需求 → 设计 → 实现 → 评估 → 讨论 → 结论 | 系统/平台论文 |
| `theory` | 引言 → 相关工作 → 形式化 → 理论分析 → 结果 → 结论 | 定理/界/反例 |
| `survey` | 引言 → 分类框架 → 方法族对比 → 挑战 → 展望 → 结论 | 综述 |

新增类型只需两份文件（`outline.md`、`manuscript.md`）加一个 `TYPES` 配置，不需要改检查器。

---

## 4 项目专属的四样东西

| 文件 | 内容 | 为什么必须项目做 |
|---|---|---|
| `facts.md` | 数据、实验、数字、来源 | 数字不能由工具编 |
| `paper_ir.json` | thesis、claims、evidence、decomposition | 主张与方法取舍是作者判断 |
| `project.json` 的 `decomposition` | 四方向或别的分解 | 项目贡献结构不同 |
| `project.json` 的 `rules` | 禁用表述、归属、边界、前作 | 每个项目的红线不同 |

`project.json` 其余字段（sections、profiles）由模板与注册表生成，作者可覆盖。

## 5 使用

```bash
# 指定期刊与学科，自动解析画像
py tools/paperkit.py new --name "某遥感论文" --dir projects/xxx \
  --type empirical --journal 测绘学报 --language zh --discipline remote_sensing

# 未知期刊：自动退回 generic_zh_*
py tools/paperkit.py new --name "某系统论文" --dir projects/yyy \
  --type systems --journal "某某学报" --language zh

# 检查
py tools/paperkit.py check --dir projects/xxx
```

`project.json` 会记录 `journal / language / discipline / profiles`，换期刊时只需改这几个字段，不必改正文结构。

---

## 6 加一个新期刊

1. 抓 100+ 摘要、50+ 全文；
2. 跑 `build_profiles.py` 与 `build_section_profiles.py`，得到 `<prefix>_abstract/method/results/discussion`；
3. 在 `registry.json` 加一条 entry；
4. 新项目带 `--journal` 即可命中。

## 7 加一个新类型

1. 在 `paperkit/templates/types/<type>/` 放 `outline.md` 与 `manuscript.md`；
2. 在 `new_project.py` 的 `TYPES` 加角色序列与默认分解；
3. `paperkit.py new --type <type>`。
