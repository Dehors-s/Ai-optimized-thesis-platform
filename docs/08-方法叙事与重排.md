# 08 · 方法叙事：为什么现在的稿子是「数据主导」，以及怎么改成「方法主线」

> 触发：读者反馈「项目数据是项目数据，论文是论文，数据是它俩的桥梁；现在数据成了主角，方法没串起来」。
> 结论：这不是措辞问题，是**组织原则**问题——现稿按项目时间线（七阶段）组织，方法被拆成七个动作；应改成按**四条设计原则**组织，数据退为每条原则的证据。

---

## 1 语料里看到的叙事结构

统计 200 篇《测绘学报》与 224 篇《自动化学报》全文的方法节（128 / 141 节）：

| 指标 | 遥感/测绘 | 计算机 |
|---|---|---|
| 方法节问题标记（针对/为了/由于/不足…） | 11.3 / 万字 | 10.3 / 万字 |
| 方法节机制标记（因为/从而/使得/核心思想…） | 11.2 / 万字 | 9.9 / 万字 |
| 方法节操作标记（采用/设置/训练/选取…） | 32.1 / 万字 | 40.6 / 万字 |
| 方法节段首「直述」占比 | 119/128 | 125/141 |

两个读数值得注意。第一，**真实论文的方法节也是操作词多于机制词**，所以「机制词少」本身不是病。第二，方法节的段首大多是直述（「本节设计……」「图 3 给出……」），并不是每段都「针对……问题」。真正的差别不在词频，而在**每一节是否有「设计约束 → 设计 → 机制 → 证据」这条链**，以及全文是否有一个**统一的原则**把各节串起来。

语料中的方法型论文通常有三件现稿缺少的东西：

1. **一个被命名的总框架**：引言末尾给出「本文方法」的名字与一句话原则，方法节首图画出组件关系，后续每节回指这个框架；
2. **每一节先给约束**：不是「我们用了什么」，而是「由于 X 约束，必须 Y，所以设计 Z」；
3. **结果按原则回收**：实验结果节按方法组件组织，而不是按实验时间顺序；每个组件都有独立的验证与失败对照。

## 2 现稿为什么是「数据主导」

| 位置 | 现稿写法 | 后果 |
|---|---|---|
| 标题与摘要 | 「工程化流程：数据挖潜、异构集成与开集配额」 | 三个名词都是动作，没有方法名与原则 |
| 第 1 章 | 贡献三条：流程链、增量账本、开集重述 | 贡献是「做了什么」，不是「提出了什么方法」 |
| 第 3 章 | 七阶段表 + 增量列 | 方法被拆成七个并列动作，没有主次 |
| 第 4–7 章 | 每节「动作 → 增量 → 定性」 | 读者记住的是数字，不是设计理由 |
| 第 8 章 | 增量账本与测量学教训 | 数据成为结论，方法退为背景 |

一句话：**现稿的目录是项目周报，不是方法论文。**

## 3 重排：四条原则，七阶段降为实例

### 3.1 方法命名与一句话原则

**方法名**：测量驱动的双高精细分类方法（Measurement-Driven Classification，MDC）。

**一句话原则**：在无验证反馈、观测非平稳、开集构造特殊的条件下，系统的上限由「可核验的决策规则」决定，而不是由单点模型容量决定；方法的核心是把每一次改动变成一次可判定的测量，并据此分配数据、模型与解码的预算。

### 3.2 四条设计原则

| 原则 | 设计约束（来自数据） | 设计动作 | 机制 | 证据 | 边界 |
|---|---|---|---|---|---|
| **P1 先测后改** | 无验证集；种子噪声 ±0.0061；代理尺可被写穿 | 噪声底、探针账本、七道闸门 | 把「是否有效」变成「是否超噪声」 | 代理尺 0.6701→0.9032；跨族符号反转 | 噪声随任务变，需重测 |
| **P2 数据先于模型** | 42 日期非平稳；8 类单日期监督 | 2×2 拼接、重叠查表、双表示与归一化 | 在输入端消解域偏移，模型只处理剩余误差 | +0.0730 / +0.0282 / +0.0238 | 查表依赖划分缺陷 |
| **P3 异构优于同质** | 同族错误高度相关 | 四族 17 成员、跨族加权 | 错误不相关才可平均抵消 | 跨族 +0.0107 vs 同族 +0.0009 | 族数受算力约束 |
| **P4 配额替代检测** | 未知类与已知类同物候；宏平均过度预测低基频 | 分位注入、21×21 平滑 | 检测不可分时，改为在指标结构下分配份额 | AUC 0.51–0.55；+0.0182；90/10 | 份额有平台，只能报区间 |

七阶段不再是目录，而是这四条原则的工程实例：P1 对应闸门与账本；P2 对应阶段①–②；P3 对应阶段③；P4 对应阶段⑥；阶段④–⑤是 P2/P3 的稳定性补丁。

### 3.3 新章节结构

| 章 | 任务 | 数据的位置 |
|---|---|---|
| 1 引言 | 三重约束 → 现有方法假设验证集 → 提出 MDC 与四条原则 | 只给任务数字，不给增量 |
| 2 问题形式化与测量环境 | 把约束写成 C1–C4，对应 P1–P4 | 数据作为「约束来源」 |
| 3 方法 | 3.1 总框架图；3.2–3.5 每条原则一节（约束→设计→机制→边界） | 不出现增量数字 |
| 4 实验 | 4.1 测量协议；4.2–4.5 按原则验证；4.6 最终结果与归属 | 数据作为证据 |
| 5 讨论 | 测量学教训、方法边界、与既有方法论文的关系 | 数据作为反例 |
| 6 结论 | 回收四条原则 | 只给最终读数 |

**关键改动**：第 3 章不再出现「+0.0730」这类增量，所有数字推迟到第 4 章；第 4 章的每一节标题是原则，不是阶段。

## 5 对写作方法（ArgFirst）的补充

这次暴露的是 v2.1 缺的**方法叙事层**。补两条规则：

1. **方法必须先有名、有原则、有组件图**，再写实现；没有名字的「七阶段」只是清单。
2. **方法节不报增量**，增量一律放到实验节；方法节只回答「为什么这样设计」，实验节才回答「值多少分」。

评分卡相应加一项 **D0 方法主线**（25 分前置项）：方法是否有名字与一句话原则、每条原则是否有约束→设计→机制→边界、结果是否按原则回收。D0 不通过，后面五项不评。
