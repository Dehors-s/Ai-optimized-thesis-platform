# 06 · 方法 v2：语料标定版

> 触发：拿真实论文跑了一遍摘要，从 v1 改到 v5，才发现原方法缺的不是「写作知识」，是**外部坐标**。
> 结论：论文质量不能靠「像不像论文」来判断，要用**同领域真实期刊的分布**来标定；原稿只提供主张与证据，不提供句子。

---

## 1. 这次实测暴露的三个问题

### 1.1 「学术化」是个形容词，不是判据

v1 的规则是「简洁、凝练、学术化」，模型只能朝「看起来像论文」优化，结果产出的是**正确的废话**：句子都对，信息量低。v2 把它换成 9 个可测指标后，「像不像」才变成「差多少」。

### 1.2 摘要与正文是两种语体

同一批《测绘学报》文章：

| 语料 | 句均长 | 逗号/句 | 的/百汉字 |
|---|---|---|---|
| 摘要（414 篇） | 75.5 | **1.49** | **3.39** |
| 正文（200 篇） | 74.9 | **2.44** | **2.68** |

摘要靠「长句 + 少逗号 + 密定语」，正文靠「多逗号 + 解释」。v4 用正文的逗号节奏写摘要，所以「重且碎」。**方法必须分账：摘要画像、正文画像各一套。**

### 1.3 原稿不能当语体参照

原稿写得差，如果以它为参照做「润色」，只会把差句子改得更顺，不会变好。正确做法是**源分离**：从原稿里只抽「主张、证据、数据、限定」，句子全部丢掉，按论证内核重新生成。

## 2. 方法修正：五条

### 修正 1：先建「语体画像」，再动笔

画像 = 同领域、同体裁、同期刊的语料统计，落成 JSON：

```json
{
  "id": "rs_abstract",
  "domain": "remote_sensing",
  "genre": "abstract",
  "n_docs": 414,
  "sentence": {"mean": 75.5, "median": 65, "p90": 134, "gt80": 0.337},
  "commas_per_sentence": 1.49,
  "de_per_100_zh": 3.39,
  "hard_rules": {"max_dash": 0, "max_quote": 0, "comma_tolerance": 0.4, "de_tolerance": 0.6},
  "soft_rules": {"sentence_mean_tolerance": 15, "gt80_tolerance": 0.2}
}
```

**硬规则**（破折号、引号、元话语、逗号、的密度）不达标不许发布；**软规则**（句均、长句占比）只扣分，因为内容需要时可以偏重。

### 修正 2：摘要与正文分开标定

- 写摘要：用 `rs_abstract` / `cs_abstract` 画像，目标是「长句、少逗号、密定语」。
- 写正文：用 `rs_body` 画像，逗号可以多 60%，的密度反而更低。
- 不要拿正文的节奏写摘要，也不要用摘要的密度写正文。

### 修正 3：源分离——原稿只出「料」，不出「句」

流程改成：

```
原稿 → 抽 claim / evidence / qualifier / rebuttal（不看句子好坏）
     → 重建 PaperIR
     → 按画像重新生成句子
```

原稿里写得好的句子可以留，但必须能挂到某个 claim 上；挂不上的，即使通顺也删。

### 修正 4：闭环从「主观觉得 AI」改成「测量—定向重写」

```
生成 → style_check 打分 → 看哪项 fail → 只改那一项 → 复测
```

每轮只动一个维度（先句长，再逗号，再的密度），避免「整篇重写」把内容改丢。v4→v5 就是这么做的：先把逗号 2.67 压到 1.5，再把句均 102 压到 79.5，的密度从 4.04 降到 3.42。

### 修正 5：内容与语体分开评分

- 论证、证据：仍由 D1/D2 与证据环管，**语体满分也不能掩盖伪造数据**。
- 语体：由画像与 `style_check` 管，**论证满分也不能带着 AI 腔发布**。
- 两者是乘法关系，不是替代关系。

## 3. 新工作流（七步）

| 步 | 动作 | 产物 | 门禁 |
|---|---|---|---|
| 1 | 选域：期刊、体裁、年份 | 目标画像 id | 语料 ≥100 篇 |
| 2 | 建画像 | `corpus/profiles/*.json` | 指标齐全 |
| 3 | 抽论证内核 | `paper_ir.json`（claims/evidence） | thesis 四要素、无孤儿 |
| 4 | 搭骨架 | 段落任务单 | 每段有 claim_ref 与 exit_belief |
| 5 | 按画像行文 | 草稿 | 数字可溯、无元话语 |
| 6 | 语体闭环 | `style_check` 报告 | 硬规则全过，软规则 ≥B |
| 7 | 证据环 + 评审环 | reviews/checks | 无 blocker |

第 6 步是这次新增的；第 3 步的「不看原句」是这次改写的。

## 5. 画像不是真理

- **分布不是规范**：画像描述「这一批期刊平均怎么写」，不证明那样写最好；它只防「一眼不是这一行的人」。
- **抽取有噪声**：PDF 的半角标点、断行、页眉会污染统计；本次已做清洗，但正文指标仍有 ±5% 误差。
- **领域要匹配**：用《测绘学报》的画像写医学论文会错；跨领域必须重建画像。
- **防指标 gaming**：只压逗号、堆「的」也能过检查，但论证会空。所以 style_check 只做**下限**，内容仍由证据环与评审环负责。

---

## 6. 与任务二的接口

- 平台新建项目时，先选「画像」（期刊/体裁/年份），画像作为项目配置存进 `project.json`。
- 编辑器右侧常驻 **style_check 仪表盘**：句均、逗号、的密度、硬规则四项，实时红/黄/绿。
- 「定向重写」按钮：只对 fail 的维度发起一次局部改写，给出 diff，人可接受/拒绝。
- 画像可随项目积累更新：投稿被拒后，把目标期刊的近期文章加入语料，重建画像。

## 7. 一句话

**v1 教模型「怎么写论文」，v2 告诉它「这一行的论文长什么样」，并用一个分数盯着它。**
