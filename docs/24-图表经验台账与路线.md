# 24 图表经验台账与路线：参考驱动，不是批量复刻

> 两个问题：经验有没有留下来？接下来是"批量复刻+人工纠正"，还是"作者先选图再复刻"？
>
> 答案：经验**部分保留**，这一版补成台账；路线**不是二选一**——
> 前端让作者从参考画廊选图，后端逐部件复刻；**批量复刻只用于内部造部件库，不做生产。**

## 2 联网核对：参考驱动是主流

| 工作 | 结论 | 对我们的意义 |
|---|---|---|
| [DiagramBank, arXiv:2604.20857](https://arxiv.org/abs/2604.20857) | 57,100 张已接收论文图；把参考池换成绩效从 4.62 提到 7.88 | **参考图库本身就能显著提升生成质量** |
| [DiagramRAG, arXiv:2605.27931](https://arxiv.org/abs/2605.27931) | 按语义 + 拓扑检索参考图，再引导生成；F1 0.848/0.802 | **检索要同时看内容和结构** |
| [ReFigBench, arXiv:2609.18844](https://arxiv.org/abs/2609.18844) | 1,000 张图复刻成可编辑 PPTX；感知仍是瓶颈；保真与可编辑难两全 | **复刻是公认难题，不是我们笨** |
| [LLM4Vis, arXiv:2310.07652](https://arxiv.org/abs/2310.07652) | 可视化推荐 + 解释，少样本即可 | 作者选图要有推荐与理由 |
| [SpotLight, arXiv:2103.11297](https://arxiv.org/abs/2103.11297) | 按"洞察"推荐图，而不是单一排序 | 画廊要按章节/意图组织 |

结论：**"整张图一次生成"不是主流；"检索参考 → 拆结构 → 生成/复刻"才是。**

## 3 路线：三段式

```
① 选    作者按章节/意图，从参考画廊选 1—3 张
② 拆    参考 → 容器/面板/共享元素 → 匹配部件库 → 缺口登记
③ 复刻  部件渲染 → 拼装 → 人工纠正 → 导出
```

### ① 选：参考画廊

已经生成 `corpus/figures/corpus/gallery.html`：

- 346 张，按类型/来源筛选，可搜图注关键词；
- 每张显示类型、期刊、中文图注；
- 点开看原图，作为"我要像这样"的参考。

作者不需要从零描述"我想要什么图"，而是**在同类图里指**。

### ② 拆：参考 → 部件

参考图拆成：容器、面板、共享色标/轴、连接、字母。
每个面板匹配部件库（CNN/分类/谱/向量场/地图/矩阵/定性网格……）。
匹配不上的登记为"缺口"，进入部件开发队列。

这一步可以半自动：VLM/OCR 辅助读容器和文字，人工确认。
ReFigBench 的结论是感知仍是瓶颈，所以**先人工测量，不假装全自动**。

### ③ 复刻：逐部件渲染 + 拼装

- 部件单独渲染、单独验收；
- 拼装器只管位置、边框、共享元素、箭头；
- 人工纠正只在部件级和版式级，不用整张重画；
- 导出 PDF，交给 Tavotto/Illustrator 微调。

---

## 4 为什么不"批量复刻全部 346 张"

1. **成本**：单张 1—3 小时，346 张不可行；
2. **数据不可得**：多数图没有源数据，只能 L1，不能 L2；
3. **复用单元是部件，不是整图**：100 张图可能只用到 12 种面板；
4. **批量复刻的产出应该是"部件 + 回归用例"，不是"346 张复刻图"**。

所以批量复刻只做**内部造库**：每类挑 10—20 张 canonical，产出 renderer + 回归用例。
生产流程永远是"作者选参考 → 拆 → 拼 → 改"。

## 5 经验台账（补上）

### 5.1 复刻 playbook

1. 固定画布尺寸，和原图同比，**不裁边**；
2. 用百分比量容器坐标，不靠目测；
3. 写 layout JSON（容器/面板/共享元素/连接）；
4. 部件单独渲染，先看部件对不对；
5. 拼装，导出 PNG/PDF；
6. 生成 50% 叠加图 + 差异图；
7. 逐项 checklist：容器、面板数、文字、色标、箭头、字号；
8. 迭代到容器误差 <1%，文字/箭头方向一致。

### 5.2 失败分类

| 编号 | 失败 | 典型表现 | 修法 |
|---|---|---|---|
| F1 | 画布裁剪 | 整体偏移、缩放不对 | 固定 figsize，不用 tight bbox |
| F2 | 容器坐标 | 标题压线、容器错位 | 百分比量，写进 layout |
| F3 | 面板密度 | 箭头太稀、格子太少 | 数原图数量，按面积调 |
| F4 | 文本重叠 | 标题压标签、标签压图 | 按容器宽度缩字号/换行 |
| F5 | 数据不可得 | 场/谱/分割是假的 | 明确标 L1，不冒充 L2 |
| F6 | 字体/公式 | 字形不对、公式排版差 | 接受近似，或用 LaTeX/mathtext |

### 5.3 回归集（待固化）

| 图 | 检查 |
|---|---|
| GMD 2×7 矩阵 | 2×7、行标签、列标题、每行色标、字母 a—n |
| SAM overview | 单行管线、加号、三掩码、score、valid masks |
| MTDL | 六容器坐标、8×8 网格、20 谱线、9 盒堆叠、分类形状 |

每张配 layout JSON + 期望结构 + overlay 分数；改部件后跑一遍。

## 6 里程碑

| 阶段 | 做什么 | 验收 |
|---|---|---|
| P0 | 经验台账 + 3 张回归集 + 参考画廊 | 文档可查、画廊可筛 |
| P1 | MTDL 迁 panelkit；补 3 个部件（地图/定性网格/时序网格）；模板 + 拼装 + 共享元素 + 色标一致性 lint | 部件可单测、拼装可跑（地图 ✅，MTDL ✅，template lint ✅，layout lint ✅，shared ✅，C13 ✅，定性/时序待补） |
| P2 | 参考 → 拆解半自动（VLM/OCR + 人工确认） | 拆一张图 <30 分钟 |
| P3 | 作者工作流：章节 → 画廊 → 选图 → 复刻 → Tavotto | 一张图 <2 小时 |

---

## 7 指标

- **部件复用率**：新图里来自部件库的面板占比；
- **复刻时间**：从选图到导出的人工分钟数；
- **结构通过率**：容器/面板/文字/色标/箭头五项；
- **作者接受率**：盲评"愿意用这张图"的比例；
- **数据保真率**：L2 图占比（有源数据的比例）。

---

## 8 一句话

**不要把 346 张图都复刻；把"选参考—拆部件—拼装—纠正"做成流程，
复刻只用于造部件和回归。经验要落成台账，不然每张图都从零开始。**
