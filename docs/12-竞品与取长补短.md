# 12 · 竞品扫描与取长补短

> 结论先说：市面上 AI 学术写作产品很多，但集中在**语言层**与**文献层**；**结构层与证据层**是空档，也是我们的位置。
> 说明：以下按各产品官网公开功能概括，未逐项试用；价格与功能以官网为准。

---

## 1 三类玩家

### 1.1 语言层（最强、最成熟）

| 产品 | 做什么 | 强项 | 缺口 |
|---|---|---|---|
| **Writefull** | 学术语言检查、改写、标题/摘要生成、LaTeX 代码 | 语言模型在数百万篇期刊文章上训练；Word/Overleaf 深度集成；Academizer 把口语改学术；1500+ 机构在用 | 只处理句子，不处理论证结构；摘要生成是事后压缩，不绑定证据 |
| **Trinka**（Enago） | 学术/技术写作语法与风格检查、投稿前检查 | 技术术语一致性、出版规范检查 | 句级，缺结构与证据 |
| **Paperpal**（Cactus） | 语言检查、改写、翻译、投稿准备 | 投稿前工作流完整，中英文入口 | 同上 |
| **秘塔写作猫** | 中文语法、润色、改写 | 中文语感好、入口轻 | 不涉及论文结构 |

**启示**：语言层是红海，不要重造。我们的分节画像（摘要/方法/结果/讨论）比“通用学术语言”更细，可以作为差异化插件，接在 Word/Overleaf 里，而不是另做一个编辑器。

### 1.2 文献层（成熟、可集成）

| 产品 | 做什么 | 强项 | 缺口 |
|---|---|---|---|
| **SciSpace** | 文献搜索、PDF 对话、引用、AI 写作 | 文献理解与问答体验 | 不负责论文结构与证据链 |
| **Elicit** | 系统性综述、数据抽取、证据表 | 证据表格化 | 不写论文 |
| **PaperQA2**（开源） | 文献检索与事实性问答 | 引用可追溯、LitQA2 基准 | 面向检索，不面向成稿 |
| **STORM**（开源） | 多视角提问 + 提纲 | 写前研究 | 提纲是主题树，不是论证树 |

**启示**：文献检索与引用落地直接接现成（Elicit/SciSpace/PaperQA2），我们只做“引用是否支持这句话”的核验。

### 1.3 模板/代写层（流量大、信任低）

| 产品 | 做什么 | 强项 | 缺口 |
|---|---|---|---|
| **Jenni AI** | 带引用的 AI 写作、提纲、续写 | 写作体验顺、引用插入方便 | 缺少证据核验与数据溯源 |
| **笔灵 AI** | 大纲→万字论文、格式排版、降重/降 AIGC | 模板多、门槛低、中文场景全 | 以“生成/降重”为目标，不保证论证与数据真实 |
| **AI Scientist / Agent Laboratory**（开源） | 端到端科研与成稿 | 自动化程度高 | 质量与可核验性不足，需人工兜底 |

**启示**：模板与体验要学（大纲可编辑、格式一键、入口轻），但定位不能是“代写/降重”——那会把产品锁进低信任区间。

## 3 取长补短：五条

1. **语言层外包，不重造**：默认接 Writefull/Trinka/Paperpal 的 API 或插件；我们只做“分节画像 + 期刊标定”，这是它们没有的粒度。若自研，也只做“学术语体”这一窄层。
2. **文献层接现成**：Elicit/SciSpace/PaperQA2 负责检索与引用候选；我们负责“引用是否支持这句话”的核验与证据表。
3. **模板 UX 学笔灵**：大纲可编辑、格式一键、模板多；但模板输出的是“结构 + 检查”，不是“全文代写”。
4. **自动生成学 Jenni/AI Scientist**：引用感知的续写、端到端流程；但每个阶段加人工确认与检查，不让模型直接交稿。
5. **检查层学 Trinka/Paperpal**：把语体、术语、数字、红线、引用五项做成“投稿前报告”，这是它们有、我们更该有的产品化形态。

---

## 4 我们的位置

```
语言层   Writefull / Trinka / Paperpal / 秘塔      ← 红海，接
文献层   SciSpace / Elicit / PaperQA2 / STORM     ← 成熟，接
结构层   论证骨架 / 四方向 / 段落任务单            ← 空档，我们做
证据层   事实清单 / 数字溯源 / 引用支持核验        ← 空档，我们做
呈现层   图表规格 / 期刊排版                       ← 部分空档
```

一句话定位：**不是又一个写作助手，而是论文的“结构与证据”层；语言和文献可以接别人，结构、标定与核验必须自己做。**

---

## 5 对 v1 的直接启示

| 竞品做法 | 落到 v1 |
|---|---|
| Writefull 的 Word/Overleaf 集成 | v1.1 提供导出与检查入口，不另造编辑器 |
| Writefull 的 Abstract/Title 生成 | 我们的摘要生成必须绑定最终 claims 与事实清单，不做事后压缩 |
| Trinka 的术语一致性 | 已有 `term_check`，下一步加“同一概念多种叫法”检测 |
| Paperpal 的投稿前检查 | `check_project` 输出“投稿前报告”，含五项 |
| 笔灵的模板与格式 | 模板已做；格式排版接 LaTeX/Quarto，不自研 |
| Jenni 的引用插入 | 下一步接文献层，做“引用候选 + 支持度核验” |
| AI Scientist 的端到端 | 保留人工确认点，不追求全自动 |

---

## 6 结论

市场不缺“会写句子的 AI”，缺“知道这篇论文该证明什么、证据够不够、写得像不像这一行”的工具。我们的 v1 不拼语言，不拼文献，拼的是**结构、标定与核验**；语言与文献通过集成解决。
