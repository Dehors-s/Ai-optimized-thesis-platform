# 05 · 中文期刊语体规则（v2）

> 触发：上一版摘要被判定「AI 味太重」。
> 结论：问题不在词，在三种结构习惯——**元话语、对偶、账本**。中文期刊有一套自己的「笨」写法，必须按它写。
> 方法修正：在 ArgFirst 的文本层里增加「中文期刊语体」子层，规则来自真实摘要语料，而不是笼统的「学术、简洁」。

---

## 0. 上一版为什么像 AI

把上一版摘要拆开看，AI 味来自五个可定位的习惯，而不是「用词不够学术」：

| # | 习惯 | 上一版的原句 | 为什么像 AI |
|---|---|---|---|
| 1 | **元话语**：评论文章本身的结构 | 「归因给出三条结论」「上述结论有明确边界」「本文的价值不在单项增益，而在……」 | 真实论文在说事，不在解说自己怎么说事 |
| 2 | **对偶句**：不是 A，而是 B | 「本文不提出新结构，而将……」「不在单项增益，而在……」 | 对仗工整、信息量低，是典型的生成式句式 |
| 3 | **符号过密**：破折号、引号、括号、分号清单 | 「（S 侧）」「（含样本量增加）」「（超出噪声底）」 | 中文期刊摘要极少用这些符号做分层 |
| 4 | **账本式数字**：七八个增量并列 | 「+0.0730、+0.0282、+0.0238，均超出噪声底」 | 像实验记录，不像叙述；读者抓不住主次 |
| 5 | **短句均匀 + 概念化收尾** | 每句 20–35 字；结尾落到「可核验的判据」 | 中文期刊摘要以长句包孕为主，结尾落在具体结论 |

一句话：**上一版是「论证报告的压缩」，不是「期刊摘要」。** 论证内核决定写什么，期刊语体决定怎么说，两者不能混。

---

## 1. 语料与观察

样本：《自动化学报》2024 年第 50 卷第 1 期（综述 2 篇、论文 6 篇）与《软件学报》2026 年第 37 卷第 11 期（当期与优先出版），合计 20 余篇中文摘要。

观察到的稳定模式：

| 位置 | 模式 | 原文例（节选） |
|---|---|---|
| 开头 | 直陈任务或问题，不用「随着……的发展」 | 「研究了 n 比特随机量子系统实时状态估计及其反馈控制的问题.」 |
| 开头 | 先给领域事实，再落到不足 | 「许多代码文件随着软件演化逐渐膨胀并承担了过多职责, 严重影响了软件的可维护性和可理解性.」 |
| 转折 | 「针对此问题 / 为此 / 为解决这一问题」 | 「传统的多模态过程故障等级评估方法对模态之间的共性特征考虑较少…… 针对此问题, 首先, 提出……」 |
| 方法 | 「提出一种……方法/框架/系统」+ 名称 | 「为此, 提出一种面向扩散语言模型的高效对比解码方法 DiffuCD.」 |
| 方法 | **首先 / 然后 / 接着 / 最后** 展开步骤 | 「首先, 建立航天器姿态指向约束模型……; 然后, 基于"角度扰动"方法设计……; 接着……; 最后……」 |
| 结果 | 「实验结果表明 / 结果显示」+ 具体数字 | 「在 72 h 内发现了 5 个缺陷, 比基线方法 DIE 和 FuzzJIT 分别多检测了 2 个和 3 个 bug.」 |
| 结果 | 分条列结果（1) 2) 3)） | 「结果表明: 1) ……提升了 11.5%; 2) ……; 3) ……」 |
| 结尾 | 「验证了……的有效性 / 优越性」 | 「验证了该方法的有效性.」「证明了其在 Android 反运行时分析中的有效性.」 |

**关键区分**：这些摘要大量使用「首先/其次/最后」，但并不显得 AI。原因是它们用连接词组织**方法步骤**，而不是组织**对论文的评论**。AI 味的来源不是连接词，是「用连接词谈论自己」。

### 1.1 语料标定（928 篇摘要，2022—2026）

从《自动化学报》《测绘学报》抓取 928 篇摘要、224 篇 PDF（911 MB）后统计得到的目标区间。这是「像不像这一行的人写的」的量化底稿：

| 指标 | 语料值 | 写作目标 |
|---|---|---|
| 摘要字数（中位 / P90） | 356 / 483 | 450–550（复杂工程论文可到 650） |
| 句均长 | 68.2 | 70–85（偏「笨重」可取上限） |
| 句长中位 | 57 | 55–70 |
| >80 字句占比 | 25.4% | 35%–55%（长句承载方法链与定语） |
| 每句逗号数 | 2.2 | 2.2–2.8 |
| 每句「的」数 | 2.13 | 2.3–2.8 |
| 「的」密度 | 3.1 / 100 字 | 2.8–3.2 / 100 字 |
| 分号密度 | 1.95 / 千字 | 2–4 个 / 篇 |
| 破折号密度 | 0.03 / 千字 | 0 |
| 高频结尾 | 「所提方法的有效性」「该方法的有效性」「有效性和优越性」 | 有效性 / 参考 |

**怎么用**：写完后按这张表量一遍。句均长偏低、>80 字比例偏低、的密度偏低，就是「太顺」；三项都达标但读起来仍假，通常是元话语没清干净。

**分领域差异**（同一语料，按期刊拆）：遥感/测绘（《测绘学报》414 篇摘要）句均 75.5、逗号 1.49/句、「的」密度 3.39/百汉字；计算机（《自动化学报》914 篇摘要）句均 67.7、逗号 2.17、「的」密度 3.69。**遥感期刊更接受长句、少逗号**——写遥感摘要时句均可取 78 左右，逗号不要切得太碎。

**摘要 vs 正文**（《测绘学报》200 篇全文）：全文句均 74.9、逗号 2.44/句、「的」密度 2.68；摘要的逗号只有 1.49、密度却更高（3.39）。也就是说，**摘要是「长句 + 少逗号 + 密定语」，正文是「多逗号 + 解释」**。用正文的逗号节奏去写摘要，会显得碎。

## 2. 中文摘要的五段式

```
① 任务/背景（1 句，具体，不空泛）
② 问题与不足（1–2 句，落到具体困难）
③ 方法（1–3 句：提出什么 + 首先/然后/最后 展开）
④ 结果（1–2 句：在什么上实验 + 实验结果表明 + 数字）
⑤ 结论（1 句：验证了什么 / 可供什么参考）
```

对应句式：

| 段 | 可套句式 |
|---|---|
| ① | 「……是……的重要环节。」「……需在……上同时……。」「研究了……的问题。」 |
| ② | 「现有方法……，导致……。」「该任务的困难在于……。」「针对……问题，」 |
| ③ | 「本文提出/构建/整理出……，首先……；然后……；最后……。」「具体而言，……」 |
| ④ | 「在……上开展实验。实验结果表明，……达到……，较……提升……。」 |
| ⑤ | 「验证了……的有效性。」「上述结果表明……，可为……提供参考。」 |

## 3. 句式库（按功能）

### 3.1 开头（选一）

- 「……是……的核心问题之一。」
- 「……需在……条件下同时满足……。」
- 「现有……方法多依赖……，在……场景下……。」
- 「研究了……的问题。」
- 「针对……中……的问题，」

**不要**：「随着……的不断发展」「在当今……背景下」「众所周知」。

### 3.2 方法与过程

- 「为此，提出一种……方法，该方法……。」
- 「本文的工作集中在……：将……整理为 N 个阶段。」
- 「首先，……；然后，……；接着，……；最后，……。」
- 「通过……，实现……，从而……。」
- 「在此基础上，进一步……。」

### 3.3 结果

- 「实验结果表明，……在……上达到……，较……提升……。」
- 「与……相比，……分别提升……和……。」
- 「在……数据集上的实验验证了……。」
- 「结果表明：1) ……；2) ……；3) ……。」

### 3.4 结尾

- 「验证了该方法的有效性。」
- 「上述结果表明，……可为……提供参考。」
- 「为……提供了一种可行路径。」

## 4. 禁则（AI 味的七个特征）

| # | 禁则 | 反例（上一版） | 改法 |
|---|---|---|---|
| 1 | 不评论文章自身结构 | 「归因给出三条结论」 | 直接写结论：「数据侧的增益最大：……」 |
| 2 | 不用对偶句 | 「本文不提出新结构，而将……」 | 「本文围绕工程流程展开，将……」 |
| 3 | 破折号 = 0，中文引号 = 0 | 「——」 | 用逗号或句号断开 |
| 4 | 括号 ≤ 2 组，且只用于术语首现的英文全称/缩写 | 「（S 侧）」「（含样本量增加）」 | 写成「总体精度（overall accuracy，OA）」；编辑性补充改用逗号 |
| 5 | 不列账本，只报 3–5 个主数字 | 七八个增量并列 | 选「最大增量 + 反例 + 关键分解」 |
| 6 | 句均长 ≥ 35 字，允许长句包孕 | 每句 20–30 字 | 用「通过……，……，从而……」把短句合并 |
| 7 | 结尾不造概念，落在具体结论 | 「可核验的判据」 | 「可为同类竞赛的工程实践提供参考」 |

## 5. 与「红线」的兼容：把元叙述改成事实句

论文有若干必须交代的事实（归属、不可迁移、前作、噪声）。它们在摘要里不应写成「本文的边界是……」，而应写成事实：

| 红线 | 元叙述写法（差） | 事实句写法（好） |
|---|---|---|
| 归属 | 「需要说明的是，最终融合的权重部分来自合作方。」 | 「最终融合中 0.40 的权重由合作方提供。」 |
| 不可迁移 | 「查表收益有边界，换干净划分即为 0。」 | 「重叠区查表利用的是训练集与测试集的空间重叠，在无重叠划分下收益为 0。」 |
| 前作 | 「本文的增量是约束条件下的落法。」 | 「按份额注入的思想已有先例，本文给出的是无未知类监督、单次提交约束下的收益边界。」 |
| 噪声 | 「每条增量都标注了是否超噪声。」 | 「上述增量均高于同配置换种子的读数波动 ±0.0061；推理侧精修仅 0.0004~0.0008，低于该波动。」 |

## 6. 机器可判规则（中文摘要）

| Rule | 条件 | 级别 |
|---|---|---|
| R-ZH-01 | 出现「——」 | major |
| R-ZH-02 | 出现中文引号「“”」 | minor |
| R-ZH-03 | 括号组数 > 2 | minor |
| R-ZH-04 | 分号数 > 3 | minor |
| R-ZH-05 | 命中元话语黑名单：本文将从 / 归因给出 / 上述结论 / 本文的价值 / 值得注意的是 / 综上所述 | major |
| R-ZH-06 | 出现对偶结构「不……而……」「不在……而在……」 | major |
| R-ZH-07 | 平均句长 < 35 字 | minor |
| R-ZH-08 | 段落数 > 2 | minor |
| R-ZH-09 | 数字个数 > 8 | minor |
| R-ZH-10 | 结尾无「验证/表明/参考/有效」类落点 | minor |

> 这些是「风格下限」，不替代内容判断。内容仍由评分卡 D1–D5 负责；语体只负责「读起来是不是这一行的人写的」。

## 7. 英文摘要的差异（简）

- 英文可以更直接：「We propose…」「Experimental results show…」。
- 同样忌：「In recent years, … has attracted increasing attention」「not only … but also …」。
- 英文摘要允许 150–250 words；中文对应 300–500 字。
