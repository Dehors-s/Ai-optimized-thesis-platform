# 19 复杂图表：真实样本、工具链与边界

> 上一版（docs/18）只做到"单张数据图"。这一版看真正的复杂图：
> Nature Communications 与 GMD（Copernicus）的 10 张图，加上 arXiv 的 12 张
> 架构/定性图，拆它们的结构，判断什么工具做得到、什么做不到。
>
> 结论先说：**复杂图的难点不在画，在"多面板的语义统一"和"拼版"；
> 文生图转矢量不是主路径；我们的位置是"面板生成 + 规格检查"，拼版交给 Tavotto。**

## 1 田野：四类复杂图

样本在 `corpus/figures/field2/`（Nature/GMD，含图注与正文引用句，见 `manifest.json`）
与 `corpus/figures/field/`（arXiv，见 `notes.md`）。

### 1.1 地图复合图（focus + context）

[Nature 中非生物量 图 1](../corpus/figures/field2/nature-central-africa-biomass-1.png)：

- **a/b**：两张同投影的洲际地图（冠层高度、变化像元比例），各自独立色标；
- **c/d/e**：三个放大区，每个区上下两层（变化量、退化年份），共用右侧三条色标；
- 黑点标出放大区位置，字母 a—e 对应；
- 底图：国界细线，经纬度刻度，无网格；海洋留白。

[Nature 河流 图 1](../corpus/figures/field2/nature-river-discharge-altimetry-1.png)：

- 上方一张 Robinson 投影全球地图，点按 KGE 分级着色，横向色标带三角端点；
- 下方 5 个评级曲线 inset，每个带统计框（KGE/nRMSE/pBIAS）与不确定带；
- 用 (b)—(f) 字母和方框/箭头把地图区域和 inset 一一连起来；
- 整张图是"总览 + 细节"，读者先看空间分布，再看典型站点的曲线。

[GMD GPP 图 1](../corpus/figures/field2/gmd-10365-2026-1.png)：

- 三张同范围全球地图，共享一个右侧色标；
- 每张图标题即方法名，左下角标全球积分（136.5 / 169.4 / 131.9 PgC/yr）；
- 只有底图有经度刻度，中间图有 "Latitude" 纵轴标题。

**共同点**：投影、范围、色标、刻度必须跨面板统一；面板靠字母/箭头连接，而不是靠读者猜。

### 1.2 矩阵小倍数

[GMD 涡度 图 2](../corpus/figures/field2/gmd-10321-2026-2.png)：

- 2 行（MPAS-O / ROMS）× 7 列（Δx = 10 km → 100 m），14 个面板；
- **列标题只在顶行出现一次，行标签只在左侧出现一次**；
- 所有面板共享同一色标（ζ/f，[-3,3]），每行一个色标；
- 面板字母 (a)—(n) 放在白底小方块里；
- 只有底行有 X 轴标签，所有面板同宽同高、同一色图；
- 面板之间是白缝，不是边框。

**这是"多面板"的标准答案**：共享的只画一次，不同的只在标题里变。

### 1.3 异质混合面板

[Nature 冠层 图 2](../corpus/figures/field2/nature-canopy-lightuse-2.png)：

- **(a)** 小提琴图 + 箱线 + 中位数点，按生物群系分组，x 标签旋转；
- **(b)** 世界地图，点按相关系数着色，底部横向色标；
- **(c)** 2×4 双轴时序小图，每格标题带站点/群系/r/T 统计，共享 "Time" 与右轴标题；
- 三种图型放在一张图里，靠字母和共享变量（r、fAPAR、A0）连起来。

**难点**：不是画小提琴或地图，而是让三种图共享一套语义（同一 r、同一配色、同一字号），
并且读者能在 30 秒内建立"地图 → 群系 → 时序"的对应。

### 1.4 架构/流程示意图

> 架构图的专门分析见 [docs/21-架构图语法与生成](21-架构图语法与生成.md)：12 个真实样本、
> 六条硬规则、`archspec` DSL 与三个 demo。

arXiv 的 12 张（见 [field/notes.md](../corpus/figures/field/notes.md)）已经总结过：
- 首图讲立场（范式对比），Fig. 2 讲结构；
- 主链 ≤7 节点 + 垂直挂载 + 虚线放大框；
- 颜色编码角色（训练/输入/预测），图例 ≤2 个算子；
- 定性结果用"同一 ROI 复制到每格 + 末列 GT"的矩阵。

## 2 复杂在哪里：六个共享

把上面几张图拆开，复杂图的成本集中在六件事上，而不是"画得花"：

1. **共享投影/范围**：地图之间必须同投影、同经纬范围，否则读者无法对照。
2. **共享色标**：同一变量跨面板必须同色标、同范围；色标只画一次。
3. **共享刻度/单位**：小倍数图只在边缘画刻度，内部面板共用。
4. **共享标签**：行标签、列标题、轴标题只出现一次，放在矩阵边缘。
5. **连接语义**：字母、箭头、ROI 框、放大引线，把"总览"和"细节"绑起来。
6. **共享版式**：面板等宽等高、白缝一致、字号三档（面板字母 > 标签 > 刻度）。

这六件事里，**没有一件是"画得像"能解决的**。它们都是布局与语义约束。

## 3 工具矩阵

### 3.1 按图层分

| 层 | 任务 | 工具 | 自动化程度 |
|---|---|---|---|
| 数据层 | 统计图、曲线、柱、热力图 | matplotlib、**MATLAB（export_fig/gramm/tiledlayout）**、R/ggplot2、seaborn、Vega-Lite | 高 |
| 数据层 | 地图、投影、栅格场 | Cartopy+matplotlib、GMT/PyGMT、NCL、MATLAB Mapping Toolbox、R (terra/raster)、QGIS | 中—高 |
| 数据层 | 三维场、地形、体渲染 | ParaView、PyVista、Blender、GMT `grdview` | 中 |
| 结构层 | 神经网络架构图 | PowerPoint/Keynote、Illustrator、draw.io、Figma、TikZ、Graphviz、Netron、PlotNeuralNet、visualkeras | 低—中 |
| 结构层 | 流程图/管线图 | Graphviz、TikZ、draw.io、我们的 `pipeline` | 中 |
| 拼版层 | 多面板对齐、标注、导出 | **Tavotto**、Illustrator、Inkscape、Affinity、PowerPoint | 低（人工为主） |
| 检查层 | 字号、色盲、单位、图注、面板自足 | 自写 lint（`figspec.py`） | 高 |

### 3.2 我们已有什么

- `figspec.py`：dot / waterfall / line / bar / heatmap / pipeline / **map**（新增）；
- 输出 PNG + SVG + **PDF**（矢量，供拼版）；
- lint：claim 进图注、轴标题/单位、尺寸、配色、0 基线、柱状图压缩差异；
- `map` 用 Natural Earth 110m 底图 + matplotlib，无 Cartopy 依赖，能画全球/区域散点图。

### 3.3 还缺什么

- **定性矩阵**（行样本、列方法、末列 GT）：需要图像网格 + 列标题 + ROI；
- **focus + context 复合**（地图 + inset + 字母连线）；
- **架构图 DSL**：节点/边/分组 + 正交路由 + 自动避让，导出 SVG/PDF；
- **三维场**（PyVista/GMT）；
- 期刊模板（单双栏、字号、图注格式）。

## 4 文生图 → 矢量：为什么不是主路径

你的猜测（文生图再转矢量）能解决"好看"，但解决不了"准确"。四个硬约束：

1. **文字保真**。科学图的核心信息是标签：方法名、维度、箭头上的 "concat"、色标单位。
   文生图最弱的就是文字。SciDraw-Bench（arXiv:2606.28406）的结论很直接：
   文本保真（OCR 标签召回、字符错误率）是所有系统最差的一维。
2. **精度**。坐标轴范围、误差条、比例尺、图例顺序，必须由数据决定。
   生成模型给的是"看起来像"，不是"算出来是"。
3. **可编辑**。生成的位图转 SVG（potrace 等）得到的是碎路径，改一个字要重画整块；
   科学图在投稿周期里平均要改 3—5 轮。
4. **可复现**。审稿人问"这条曲线对应哪次实验"，生成模型答不出来；
   而我们的整条链路（claim → evidence → figure spec）正是为了回答这个问题。

**可以用的地方**：概念草图、封面、背景纹理、示意图的第一版灵感。
**不能用的地方**：数据图、地图、架构图、任何带数字或标签的图。

正确的替代不是"更好的文生图"，而是：

```
FigureSpec（结构化） → 确定性渲染（SVG/PDF/300dpi PNG） → 人工拼版/微调
```

## 5 顶刊的图是矢量吗？一个实测

下载 GMD 论文 PDF（`corpus/figures/field2/pdf/gmd-10321.pdf`），用 PyMuPDF 检查
含 "Fig. 2" 的页面：

```
page 9: images=1, drawings=0
        img 2067 x 1414 jpeg 2.27 MB
page 12: images=2, drawings=0
        img 2067 x 648 png
        img 2067 x 881 png
```

也就是说：**这张 14 面板的涡度图，在正式 PDF 里是一张 2067×1414 的栅格 JPEG**，
页面里没有矢量绘图对象。顶刊并不要求作者提交纯矢量；生产环节也会栅格化。

### 5.2 架构图：矢量骨架 + 栅格素材

再看 HyperFree 的 PDF（`corpus/figures/field2/pdf/hyperfree.pdf`）：

```
page 1 (Figure 1, 三行范式对比): images=10, drawings=75
page 4 (Figure 2/3, 数据引擎):   images=21, drawings=60
```

图片对象是卫星影像小图/图标，绘图对象是框、箭头、文字。
也就是说，架构图不是"一张生成图"，而是**矢量版式 + 嵌入栅格素材**的混合体。
能做这件事的工具必须同时擅长两样：精确的框/箭头/文字，以及图片裁剪与嵌入。
这正是 PowerPoint、Illustrator、draw.io、Figma、TikZ（`\includegraphics`）的领域；
文生图不提供可编辑的图层结构，也不提供"这个框对齐那个框"的约束。

### 5.3 对我们的含义

- "矢量"不是目的，**分辨率 + 版式 + 文字清晰**才是；
- 地图/场图用 300—600 dpi 栅格完全可接受（GMD 正式 PDF 就是栅格）；
- 架构图仍建议矢量骨架（文字锐利、便于改），栅格素材作为嵌入层；
- 拼版工具（Tavotto/Illustrator）导出矢量 PDF 或高 dpi PNG 都能满足要求；
- `figspec` 输出 PDF 时，框/箭头/文字是矢量的，符合这个要求。

## 6 Tavotto：拼版层的现成答案

本地安装：`D:\Tavotto`，版本 **0.20.0**（`tavotto-cli.exe doctor --json`）。

它做的事正好是我们缺的那一层：

- 扫描目录里的 **PDF（矢量）与 PNG/JPG 面板**；
- 浏览器画布上拖拽、缩放、对齐、加标注；
- 导出**出版级 PNG（可选 DPI）与真矢量 PDF**；
- 支持把生成脚本登记成"图"，双击进图内编辑（需要脚本注册表）。

### 6.1 和我们怎么接

```bash
# 1) 每张图先渲染成独立面板（PDF 是矢量）
py tools/figspec.py render --spec figures/specs/F1.json --out figures/panels

# 2) 交给 Tavotto 拼版
"D:\Tavotto\sidecar\Tavotto\tavotto-cli.exe" open figures/panels
# 或直接启动桌面版，在界面里选择 figures/panels 目录：
"D:\Tavotto\Tavotto.exe"
```

实测：`open --no-launch --no-probe figures/demo/F1.pdf` 能把面板登记进项目；
若没有对应脚本，会提示"只能当素材排版，双击进不去图内编辑"——这对我们是可接受的，
因为面板由 `figspec` 生成，拼版才是 Tavotto 的职责。

### 6.2 边界

- Tavotto 不做数据绑定，不检查图注与 claim 是否一致；
- 它不管"这张图该不该画"；
- 它的强项是几何对齐、留白、标注、导出——正是脚本最难做好的部分。

## 7 建议的流水线（三层）

```
Layer 1  面板生成
         figspec（统计图/地图/管线）+ 专用渲染器（Cartopy/GMT/TikZ/PyVista）
         → 每张面板一个 PDF + 一个 FigureSpec JSON

Layer 2  语义检查
         claim 绑定、图注三段式、字号/色盲/单位/0 基线/面板自足
         → lint 不过不进入拼版

Layer 3  拼版
         Tavotto（首选，本地、矢量导出） / Illustrator / Inkscape
         → 多面板对齐、字母、共享色标、ROI、导出

Layer 4  读回
         遮住图注问：这张图说明了什么？答不出 → 回 Layer 1
```

关键分工：**脚本负责"每个面板正确"，人负责"面板之间一致"，lint 负责"别犯低级错误"。**

## 8 分阶段落地

| 阶段 | 做什么 | 为什么先做 |
|---|---|---|
| P0 | `map` 面板 + PDF 输出 + Tavotto 交接文档 | 地学论文的门面；已验证可跑 |
| P0 | `matrix` 定性网格（行样本/列方法/末列 GT） | 遥感分类论文最常见的结果图 |
| P1 | focus + context 模板（地图 + inset + 字母连线） | Nature 式复合图的核心结构 |
| P1 | 架构图 DSL（节点/边/分组/正交路由） | 计算机论文的门面，TikZ 门槛太高 |
| P2 | 三维场（PyVista/GMT） | 地学三维可视化 |
| P2 | 期刊模板（单双栏、字号、图注格式） | 投稿前的最后一公里 |
| P3 | 文生图"草图模式" | 只做灵感，不进入交付链路 |

## 9 版式从哪来

复杂图的版式不是凭空设计的，而是从顶刊语料里统计出来的。
见 [docs/20-图表模板库](20-图表模板库.md)：65 张 GMD/ESSD 图的统计、复杂度预算、12 个模板与选择器。

## 10 一句话

**复杂图 = 数据层（可编程）+ 语义层（共享色标/轴/标签）+ 版式层（拼版工具）。
三层分开，才可能既自动又好看；混在一起，就只能靠人硬画。**
