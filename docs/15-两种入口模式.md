# 15 · 两种入口模式：模板稿 vs 项目稿

> 回答一个流程问题：素材少时只加载通用模板；有项目数据时，除了模板还要加载**这个项目的创新点**。
> 结论：**之前不是这个流程**——模板总是加载，创新点是空的、靠人手填，也没有“素材少”的分支。现在按两种模式拆开。

---

## 1 之前的流程（有问题）

```
new_project → 类型模板 + 通用 facts/IR → 作者手填 thesis/claims → 写 → 检查
```

问题：

- 没有区分「素材少」与「有项目数据」；
- 创新点没有独立产物，`paper_ir.json` 里空着；
- AI 没有“从材料提炼创新点”的步骤；
- 检查器对空 claims 只报错，不区分“模板稿”与“项目稿”。

---

## 2 现在的两种模式

### 模式 A：模板稿（素材少）

```
new --mode template
  → 类型模板 + 通用画像
  → 只产出结构（章节、任务单、占位）
  → 不要求 facts / innovation / claims
  → 报告标注「模板稿，不可作为投稿稿」
```

用途：开题、提纲、结构参考。**不生成无依据的正文**。

### 模式 B：项目稿（有数据）

```
new --mode project
  → 类型模板 + 期刊画像
  → ① 事实清单（人确认数字）
  → ② 创新点候选（AI 提炼，p7 提示词）
  → ③ 作者决定：接受 / 改写 / 拒绝
  → ④ 接受的创新点写入 paper_ir 的 thesis/claims
  → ⑤ 按分解写正文
  → ⑥ 检查（创新点 ≥1、claims、语体、术语、数字、规则）
```

用途：真实论文。**模板提供结构，项目提供创新点与证据。**

---

## 3 流程图

```
素材少 ──► 模板模式 ──► 结构稿（明确标注不可投稿）

有项目数据 ──► 项目模式
                 │
                 ├─ facts.md（数字、来源）
                 ├─ innovation.md（AI 提名 → 作者决定）
                 ├─ paper_ir.json（thesis / claims / decomposition）
                 ├─ 类型模板 + 期刊画像
                 └─ 正文 → 检查 → 定向重写
```

---

## 4 创新点层为什么必须独立

- 它是**作者意愿与 AI 总结的交界**：AI 可以提名，作者必须决定；
- 它是**论证的入口**：没有接受的创新点，thesis 与 claims 就没有来源；
- 它是**审稿的靶子**：每条创新点都带证据、差异、强度、风险，审稿人可以直接打。

`innovation.md` 的字段：类型、主张、证据、差异、强度、风险、作者决定。检查器只认「作者决定：接受」的条目。

---

## 5 检查器的模式差异

| 检查项 | 模板模式 | 项目模式 |
|---|---|---|
| 结构文件 | 必需 | 必需 |
| 摘要/分节语体 | 有画像就查 | 有画像就查 |
| 术语 | 查 | 查 |
| 数字溯源 | 查（facts 为空则跳过） | 查 |
| 创新点 | 不要求 | **≥1 条接受，否则不通过** |
| claims | 不要求（提示） | **必须填写，否则不通过** |
| 红线 | 查 | 查 |

模板模式的报告顶部会写「模板稿，不可作为投稿稿」，避免被误用。

---

## 6 使用

```bash
# 素材少：只要结构
py tools/paperkit.py new --name "开题草稿" --dir projects/xxx \
  --type empirical --mode template --journal 测绘学报 --language zh

# 有数据：项目稿
py tools/paperkit.py new --name "某遥感论文" --dir projects/yyy \
  --type engineering --mode project --journal 测绘学报 --language zh --discipline remote_sensing
# 然后按 p7 提炼创新点，填 innovation.md，再做 paper_ir
```

---

## 7 一句话

**模板模式给结构，项目模式给结构 + 创新点；创新点由 AI 提名、作者决定，检查器只认作者接受的那一条。**
