# 20 图表模板库：从顶刊语料里长出来的版式

> 你说得对：图的复杂度应该由内容决定，顶刊的图是最好的模板。
> 这一版不再凭感觉，而是把顶刊图表当成语料：批量抓、按结构统计、抽模板、做选择器。
>
> 先给结论：**346 张图里，中位数只有 1 个面板，62% 是单面板，≥6 面板的只占 5%。**
> 加入 arXiv 后，"简单图是常态"更明显了。
> 复杂图是少数，而且都有明确的内容理由。模板库的价值不是把图做复杂，
> 而是"该复杂的时候有章法，该简单的时候敢简单"。

---

## 1 语料怎么建

`tools/crawl_figures.py`：

1. Crossref 找开放获取文章（Copernicus 系列 + Nature Communications）；
2. Copernicus：抓文章 HTML 里的 `<div class="fig">`，取图与图注；
3. Nature：走 Europe PMC 的全文 XML，取 `<fig>` 与图注，再从 Springer 图片 CDN 下载；
4. 统一存 `corpus/figures/corpus/{journal}/`，元数据写 `manifest.jsonl`。

当前样本：**346 张**——arXiv 146、GMD 121、ESSD 55、Ocean Science 12、
NHESS 11、ACP 1。Copernicus 提供地学复合图，arXiv 提供计算机/遥感单图与架构图。

统计口径（`tools/analyze_figures.py`）：

- **面板数**：从图注里的 `(a)(b)…` 估，没有字母记 1；
- **长宽比**：图片像素宽高比；
- **图注长度**：按词/汉字计；
- **结构类型**：图注关键词（map / timeseries / distribution / architecture / qualitative / profile …）。

偏差要说清楚：以地学 OA 为主；图注分类是粗分类；没有"好看"的机器评分。
所以下面的数字看**趋势**，不要看小数点。

## 2 统计说明了什么

| 指标 | 结果 | 含义 |
|---|---|---|
| 面板数中位数 | **2** | 顶刊图的常态是"一张图说一件事" |
| 单面板占比 | **62%**（213/346） | 简单图不是偷懒，是主流 |
| 1—2 面板占比 | **74%**（257/346） | 大多数图不超过 2 个面板 |
| ≥6 面板占比 | **5%**（17/346） | 复杂图是少数，只在矩阵/定性/时序网格里 |
| 长宽比中位数 | **1.56** | 略宽于 3:2；竖版占 15%（53/346） |
| 图注长度中位数 | **47 词** | 图注不短，但也不写小作文 |
| ≤40 词占比 | **44%**（151/346） | 单面板图的图注通常很短 |
| 类型分布（196 张已标） | 架构 29%、地图 25%、分布 14%、定性 13%、散点 7%、其他 5%、热力图 3%、剖面 2%、时序 2%、评估 1% | 地学 96 + arXiv 100 |

类型 × 面板数（节选）：

| 类型 | 常见面板数 | 解释 |
|---|---|---|
| 架构/流程 | **1**（6/8） | 一张图讲清结构，不需要多面板 |
| 时序 | 1—4 | 单站一条线，多站才开网格 |
| 地图 | 3—4 | 多方法/多变量对比才铺开 |
| 分布 | 1—4 | 小提琴/箱线通常单张或分组 |
| 复合（comparison/scatter） | 4—6 | 多证据并置才复杂 |

**三条结论：**

1. **简单是常态。** 62% 单面板、74% 不超过 2 个面板。复杂不是目标。
2. **复杂度跟着内容走。** 架构图几乎都是单张；地图和定性结果才会铺成 3—4 个面板；
   只有系统比较（矩阵、时序网格）才到 6 个以上。
3. **图注不是越长越好。** 中位数 47 词；44% 在 40 词以内。
   图注长度随面板数增长，不随"想说的话"增长。

**两个领域的类型差异极大**：

| 子集 | 主要类型 |
|---|---|
| 地学 96 张（GMD/ESSD/NHESS） | 地图 44%、分布 23%、架构 10% |
| arXiv 100 张（遥感/高光谱 CV） | 架构 47%、定性 24%、地图 7%、分布 6% |

所以模板库必须同时覆盖 **T01/T05/T07（地学地图）** 和 **T09/T10（CS 架构与定性网格）**；
只做地图模板会漏掉一半，只做架构模板也同理。

**分类器状态**：196 张标注后，5 组模型留一法 **71%**（多数类基线 29%）；
全语料 346 张预测里，低置信度（margin < 0.05）从 64% 降到 **39%**。
但仍只建议"预填 + 人工抽检"，不用于最终统计。

## 3 复杂度预算

在选模板之前，先过一道预算：

- **一个主 claim → 一个主面板。** 主图只回答一个问题。
- **每个支撑 claim 最多一个面板。** 没有新问题的面板，合并或删掉。
- **超过 4 个面板，必须属于三种结构之一**：矩阵小倍数、定性网格、时序网格。
- **面板数不是质量指标。** 审稿人问的是"每个面板是否必要"，不是"图够不够大"。

一句话：**每加一个面板，都要能说出它回答了哪个与前一个不同的问题。**

## 5 选择器与骨架预览

```bash
py tools/figtemplate.py list
py tools/figtemplate.py match --spatial --panels 5
py tools/figtemplate.py render T07_focus_context --out figures/templates/T07.png
```

`match` 的输出，例如：

```
 9  T07_focus_context      总览 + 细节   空间总览 + 细节
10  T09_qualitative_grid   定性矩阵      定性结果用矩阵
 5  T05_matrix             矩阵小倍数    多条件矩阵
```

选择顺序（也是 `match` 的判断顺序）：

```
有结构/流程？        → T10
定性结果？           → T09
有空间数据？
  单图               → T01
  多方法/多变量      → T04 / T05
  空间 + 典型细节    → T07
有时间序列？
  单序列             → T01
  多站点/多条件      → T11
只有分布/关系？      → T01 / T12
其余按面板数        → T02 / T03 / T04 / T05
```

`render` 画的是**占位骨架**：每个矩形是一个面板，字母是阅读顺序，
标题下注明"面板由 figspec 生成 PDF，再交给 Tavotto/Illustrator 拼版"。

## 6 模板怎么填

三步：

1. **每个面板单独渲染**（`figspec` 或专用脚本），输出 PDF；
2. **按模板摆位**，把共享元素做成显式槽位：共享色标、共享轴、行列标签、字母；
3. **拼版导**：Tavotto（本地 0.20.0）拖拽/对齐/标注，导出矢量 PDF 或高 dpi PNG。

共享语义清单（六个"只画一次"）：

- 投影与范围；
- 色标与范围；
- 刻度与单位；
- 行标签 / 列标题；
- 连接语义（字母、箭头、ROI）；
- 字号三档（面板字母 > 标签 > 刻度）。

这六条不统一，面板再多也不好看；统一了，简单图也立得住。

## 8 还缺什么

- 模板目前只给骨架，**自动摆位**还没做；拼版仍靠 Tavotto/人工；
- 语料以地学 OA 为主，Nature 正刊、IEEE TGRS、遥感学报还没进；
- 图注关键词分类较粗（34% 落在 other），需要人工抽检校准；
- "好看"没有可靠自动指标，只能小样本人工盲评；
- 模板与期刊格式（单双栏、字号、图注样式）还没绑定。

下一步建议：把语料扩到 300+（加 Nature Comms、MDPI Remote Sensing、IEEE OA），
人工标注 100 张的结构类型，再把 T05/T07/T09 三个模板做成"填面板 → 出预览"的半自动流程。

## 8.5 “人工标 100 张、校准分类器”是什么意思

不是训练模型，是**给规则打分**。

- **自动分类**：现在 `analyze_figures.py` 用图注关键词猜类型（map/timeseries/architecture…）。
  关键词规则一定有错，问题是有多少错、错在哪一类。
- **人工标 100 张**：从语料里随机抽 100 张图，人看图注和缩略图，给每张填一个类型。
  不是标框、不是标像素，就是填一个词。100 张大约 1—2 小时。
- **校准**：把"自动判的"和"人标的"对比，算准确率和混淆矩阵。
  比如发现 20 张标成 map 的里，有 8 张其实该是 other，就改关键词规则；
  改完再抽 30 张复核。目标不是 100% 正确，而是**知道偏差在哪、错得可控**。
- **为什么是 100**：10 张看不出比例；100 张能看出 ±10% 的系统偏差，足够判断规则能不能用。
  真要做到统计显著，再扩到 300—500。
- **操作**：

```bash
py tools/analyze_figures.py --export-labels 100
# 打开 corpus/figures/corpus/labels.csv，填 label 列
py tools/analyze_figures.py --score-labels corpus/figures/corpus/labels.csv
```

如果以后换成学习式分类器，这 100 张就是训练/验证集；现在只是先用它校准规则。

### 第一次校准结果（96 张已标）

| 方法 | 准确率 | 说明 |
|---|---|---|
| 关键词规则（11 类） | **40%** | 比“全猜 map”还差 |
| 关键词规则（5 组） | **45%** | 多数类基线是 **48%** |
| TF-IDF 质心（5 组） | **62%** | 留一法；空间↔统计仍混 |

结论：

1. **关键词规则不能再用**——它低于多数类基线。
2. 换成 `tools/figure_classifier.py`（纯 Python，TF-IDF 质心），模型存在
   `paperkit/figures/figure_classifier.json`；`predict` 会给出相似度和领先幅度，
   领先 <0.05 的标记为"建议人工复核"。
3. 62% 仍不足以自动统计 300+，但可用于**预填 + 人工抽检**：
   高置信度直接采用，低置信度进标注队列。
4. 单标签对复合图有天然局限：96 张地学图里至少 15 张是“地图+分布/剖面+时序”的复合图；
   5 张 `other` 是配置文件文本截图，不是图。复核清单见
   `corpus/figures/corpus/review_ambiguous.html`。

### 第二次校准结果（196 张：地学 96 + arXiv 100）

| 方法 | 准确率 | 说明 |
|---|---|---|
| TF-IDF 质心（整段图注） | **67%** | 留一法；多数类基线 **29%** |
| TF-IDF 质心 + **图名加权** | **71%** | 图名重复两次 + 整段图注 |
| 低置信度占比（346 张） | **39%** | 比只用地学训练时的 64% 明显下降 |

**图名有用**：只用图注第一句 65%，只用整段 67%，把图名重复两次再加整段 **71%**。
说明面板描述（(a)(b)…）是噪声，图名才是分类的主信号。

混淆集中的地方：统计↔空间（15 张统计被判空间、9 张空间被判统计），
结构类 50/57 正确，定性类 17/25 正确。仍然只适合预填和抽检。

下一步分类体系应改成：**主类型 + 次类型 + text 类**；
复合图在模板选择时走 T12（统计混合）或 T07（空间+细节）。
